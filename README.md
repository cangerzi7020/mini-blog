# 课堂笔记库

纯 Markdown 的课堂笔记库：笔记、索引、模板与校验脚本都在一个目录里，可以用 VS Code、Typora、Obsidian 打开，也可以直接用 Git 做版本管理。

## 设计原则

- **单一事实来源**：结构、模板、索引各只有一份。笔记在根目录，模板是 `_note-template.md`，索引是 `_index.md`。
- **索引由脚本生成**：`_index.md` 的表格从笔记 Front Matter 推导，不手填，避免索引与笔记漂移。
- **可校验**：命名、元数据、链接、术语重复、索引一致性问题由 `python tools/notes.py check` 统一检查，不靠人记规则。
- **纯文本**：公式用 LaTeX（`$...$` / `$$...$$`），图表用 Mermaid，不用二进制附件。

## 目录结构

```
.
├── README.md                    # 本文件：唯一规范
├── _index.md                    # 唯一索引（自动区块 + 手工维护记录）
├── _note-template.md            # 唯一笔记模板
├── _tags.md                     # 标签词表
├── tools/notes.py               # 校验与索引重建
├── YYYY-MM-DD-英文slug.md        # 笔记（根目录，可多篇）
├── 2026-11-12-linear-regression.md   # 示例笔记，首篇真实笔记后可删
└── archive/                     # 废弃结构存档，不参与检索
```

## 快速开始

1. 复制 `_note-template.md` 为 `YYYY-MM-DD-英文slug.md`，放在根目录。
2. 填写 Front Matter 与三段正文，替换全部 `{{ }}` 占位符，删除模板提示行。
3. 运行 `python tools/notes.py index` 刷新索引。
4. 运行 `python tools/notes.py check`，确保 0 错误再提交。

## 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 笔记 | `YYYY-MM-DD-英文slug.md` | `2026-11-12-linear-regression.md` |
| slug | 小写、连字符分隔、只含 `a-z0-9-`、不用拼音 | `ai-coding`、`gradient-descent` |

- 日期取上课当天，与 Front Matter 的 `date` 必须一致。
- 同一主题多次课按日期区分，不覆盖旧文件。
- 中文标题写在 Front Matter 的 `title` 里，不写进文件名，避免路径编码问题。

## Front Matter 约定

```yaml
---
title: 线性回归            # 必填，中文标题
course: 机器学习           # 必填，课程或场景，索引按它分组
date: 2026-11-12          # 必填，与文件名日期一致
instructor: 张老师         # 选填，建议填写
tags: [机器学习-回归-方法]  # 必填，见 _tags.md
status: 已整理             # 必填，草稿 | 已整理 | 已复习
---
```

| status | 含义 | 下一步 |
| --- | --- | --- |
| `草稿` | 课上速记，可能有空缺 | 课后补全后改为 `已整理` |
| `已整理` | 正文完整、术语与资料已补齐 | 进入复习队列 |
| `已复习` | 已通读并确认理解 | 移出复习队列 |

## 笔记结构

固定三段，缺任何一段 `check` 都会报错：

| 章节 | 内容 | 要求 |
| --- | --- | --- |
| 一、笔记内容 | 本次要点 / 正文 / 重点与易错点 / 疑问与待办 | 要点 3–7 条，每条可独立读懂；待办用 `- [ ]` |
| 二、名词解释 | 名词 / 英文 / 解释 / 备注 | 术语只在首次出现的笔记里定义一次 |
| 三、参考资料 | 编号 / 类型 / 标题 / 来源 / 年份 / 位置 / 链接 | 编号 `R001` 递增，写清「核对什么」 |
| 修订记录 | 日期 / 修改内容 | 每次改动追加一行 |

术语被其他笔记复用时，用链接指向首次定义处，例如 `[梯度下降](2026-11-12-gradient-descent.md)`，不要再写一遍定义——重复定义会被 `check` 判为错误。

## 索引与校验

| 命令 | 作用 |
| --- | --- |
| `python tools/notes.py check` | 校验全部笔记与索引，0 错误才算通过 |
| `python tools/notes.py index` | 重建 `_index.md` 的自动区块 |
| `python tools/notes.py` | 等同 `check` |

`check` 覆盖的规则：

| 类别 | 检查项 |
| --- | --- |
| 命名 | 文件名符合 `YYYY-MM-DD-英文slug.md`，日期有效 |
| 元数据 | `title / course / date / tags / status` 齐全，日期与文件名一致，status 合法 |
| 结构 | 三段章节与修订记录齐全，无 `{{ }}` 残留 |
| 标签 | 三段式、类型合法、已在 `_tags.md` 登记 |
| 术语 | 同一名词不得在多篇笔记重复定义，解释不能为空 |
| 资料 | 编号格式 `R\d{3}` 且不与其他笔记冲突 |
| 链接 | 文内相对链接的目标文件真实存在 |
| 索引 | 五个自动区块与笔记内容一致 |

索引里的 `<!-- AUTO:xxx -->` 区块由脚本生成，手改会在下次 `check` 时被判为「索引未同步」。需要人工维护的只有「维护记录」一张表。

## 维护流程

| 时机 | 动作 |
| --- | --- |
| 课上 | 用模板建当日文件，只记要点和疑问，`status: 草稿` |
| 课后 | 补全正文和公式，填名词解释与资料，改 `status: 已整理`，跑 `index` + `check` |
| 每周 | 看 `_index.md` 的「复习队列」，清掉草稿积压 |
| 复习前 | 按「复习队列」从上到下过一遍，通读后改 `status: 已复习` |

## 可选工具

- **VS Code** + Markdown All in One：目录生成、表格格式化。
- **Obsidian**：以本目录为仓库打开，关系图开箱可用（`.obsidian/workspace*` 已在 `.gitignore`）。
- **Git**：建议每次 `index` + `check` 通过后提交；可把 `python tools/notes.py check` 加进 pre-commit 钩子。

## 编码约定

- 全部文件 UTF-8 无 BOM。
- 标题用 ATX（`##`），表格用管道表，任务列表用 `- [ ]`。
- 不引入 HTML、图片二进制或专有格式；图表一律 Mermaid。
